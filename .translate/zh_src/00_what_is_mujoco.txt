**不需要任何物理仿真经验。**

本教程会从零带你弄明白三件事：MuJoCo 能做什么、它为什么存在、该怎样去想它——每一步都配有你能亲眼看到的动手例子。

## MuJoCo 解决什么问题？

假设你要造一个机器人。真去造一台实体机器人之前（又贵、又慢、还容易摔坏），你多半会想先：

1. **测试**你的机器人设计到底能不能走/抓/飞
2. 用上百万次试错**训练**一个 AI 控制器
3. **预测**机器人和物体相互作用时会发生什么

MuJoCo 是一个**物理仿真器**——它计算物体在受力、重力和接触作用下的运动，回答的正是这个问题：*"如果我施加这个力，接下来会发生什么？"*

### 为什么偏偏选 MuJoCo？

| 特性 | 为什么重要 |
|---------|---------------|
| **快** | 比实时快 10-100 倍——训练机器人只要几分钟，而不是几年 |
| **接触精确** | 触碰、滑动、弹跳都模拟得很真实 |
| **稳定** | 哪怕是复杂机器人，也不会"炸掉"或算出垃圾结果 |
| **GPU 并行（MJX）** | 在一块 GPU 上同时仿真 10,000 个机器人 |
| **免费且开源** | Apache 2.0 许可，由 Google DeepMind 维护 |

## 核心思路：描述 → 仿真 → 观察

用 MuJoCo 永远都是这三步：

```
1. DESCRIBE    →    2. SIMULATE    →    3. OBSERVE
   (what exists)       (advance time)       (read results)
```

## 两个核心对象

MuJoCo 只有**两个**核心数据结构。理解了它们，就等于拿到了理解一切的钥匙：

### `MjModel` —— 蓝图（不改变）

包含仿真过程中保持**恒定**的一切：
- 存在多少个物体、它们的形状和大小
- 质量、摩擦、刚度
- 关节类型与限位
- 重力、仿真步长设置

**类比：** 一栋楼的建筑图纸——它告诉你楼里有什么，却不告诉你人此刻站在哪里。

### `MjData` —— 快照（每一步都在变）

包含随时间**变化**的一切：
- 当前的位置（`data.qpos`）和速度（`data.qvel`）
- 当前的时间（`data.time`）
- 力、接触、传感器读数
- 控制信号（`data.ctrl`）

**类比：** 监控摄像头的一帧抓拍——告诉你*此刻*每样东西都在哪里。

## 基本构件：刚体、关节、几何体

每个 MuJoCo 世界都由三种基本构件组成：

| 概念 | 它是什么 | 现实世界类比 |
|---------|-----------|-------------------|
| **刚体（Body）** | 一个可以运动的刚性坐标系 | 你骨架里的一块骨头 |
| **关节（Joint）** | 连接刚体，允许特定的运动 | 膝盖或手肘 |
| **几何体（Geom）** | 附着在刚体上的形状（用于碰撞与外观） | 骨头上的肉/皮肤 |

**发生了什么：**
- 我们创建了一个**刚体（body）**——就是那条手臂
- 给它加了一个**旋转关节（hinge joint）**——它就能绕一根轴转动（像门合页）
- 给它加了一个**几何体（geom）**——胶囊形状，于是它有了质量，也看得见
- 剩下的交给重力！

### 关节类型

| 关节类型 | 自由度 | 例子 |
|-----------|-------------------|--------|
| `free` | 6（任意移动 + 任意转动） | 无人机、被抛出的球 |
| `hinge` | 1（绕轴转动） | 门、手肘、轮子 |
| `slide` | 1（沿轴平移） | 抽屉、活塞 |
| `ball` | 3（朝任意方向转动） | 肩膀、髋部 |

## 加入控制：让东西按你的意图动起来

到目前为止，动东西的只有重力。要**控制**一个机器人，就得有**执行器（actuator）**——也就是往关节上施加力的马达。

###CELL 19
**控制回路的套路**——MuJoCo 里所有机器人控制都是这么写的：

```python
while simulating:
    # 1. READ: Get current state from data
    angle = data.qpos[0]
    
    # 2. DECIDE: Compute what force to apply
    command = my_controller(angle, target)
    
    # 3. ACT: Set the control signal
    data.ctrl[0] = command
    
    # 4. STEP: Let physics happen
    mujoco.mj_step(model, data)
```

## 理解 `qpos` 和 `qvel`（广义坐标）

你会到处都是 `data.qpos` 和 `data.qvel`，可以这样建立直觉：

- **`qpos`** = 描述构型的所有位置/角度
- **`qvel`** = 全部速度（每个位置变化得有多快）

对一个**旋转关节**：`qpos` 有 1 个数（以弧度计的角度）  
对一个**自由关节（free joint）**：`qpos` 有 7 个数（x、y、z + 四元数旋转）

| 关节 | qpos 条目 | qvel 条目 |
|-------|-------------|-------------|
| hinge | 1（角度） | 1（角速度） |
| slide | 1（位置） | 1（线速度） |
| free | 7（位置 + 四元数） | 6（线速度 + 角速度） |
| ball | 4（四元数） | 3（角速度） |

⚠️ **注意：** `free` 和 `ball` 关节的 `qpos` 和 `qvel` 长度*不一样*！因为旋转要用 4 个数（四元数）来表示，描述它的变化率却只要 3 个数。

## 小结：MuJoCo 的心智模型

```
┌─────────────────────────────────────────────────────────┐
│                    YOUR CODE                             │
│                                                         │
│  1. Write XML (once)  ──►  model = MjModel(xml)        │
│                                    │                    │
│  2. Create state      ──►  data = MjData(model)        │
│                                    │                    │
│  3. Loop:                          ▼                    │
│     ┌──────────────────────────────────────┐            │
│     │  Read: angle = data.qpos[0]          │            │
│     │  Decide: command = controller(angle)  │            │
│     │  Act: data.ctrl[0] = command          │            │
│     │  Step: mj_step(model, data)           │ ◄── repeat│
│     │  (Optional) Render: renderer.render() │            │
│     └──────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────┘
```

### 关键术语

| 术语 | 含义 |
|------|--------|
| **MJCF** | 用来描述模型的 XML 格式 |
| **MjModel** | 编译后的模型（恒定的蓝图） |
| **MjData** | 仿真状态（每一步都在变） |
| **qpos** | 广义位置（所有关节的角度/位置） |
| **qvel** | 广义速度 |
| **ctrl** | 发送给执行器的控制信号 |
| **mj_step** | 把物理往前推进一个仿真步长 |
| **mj_forward** | 在不推进时间的前提下重新计算派生量 |
